Saved Sets

The Saved Sets screen lets you save reusable groups of transaction conditions. A set can be used to quickly open a filtered transaction list, review analytics for the matching transactions, or apply bulk changes to all matching transactions in one place.

In the app, this feature is labeled "Sets".

Accessing the Saved Sets Screen

You can access this screen by:

  • Going to More
  • Opening Advanced Features
  • Tapping Sets

Note: Sets is a Pro feature.

What a Saved Set Does

A saved set stores:

  • An optional date range
  • Include conditions that define which transactions should match
  • Exclude conditions that remove unwanted transactions from the result

Once saved, the set becomes a reusable filter. Instead of rebuilding the same search again and again, you can open the set and immediately work with the matching transactions.

Common uses include:

  • Reviewing all grocery spending from selected accounts
  • Finding transactions for specific contacts or tags
  • Building a temporary work set for cleanup or re-categorization
  • Applying bulk changes to many matching transactions at once

Screen Layout

The main screen shows all of your saved sets as a vertical list of cards.

Help Card

A dismissible help card can appear at the top (and as the empty-state content when you have no sets yet). It explains building include/exclude conditions, opening matching transactions or analytics, and using mass update, with short example set ideas.

  • Dismiss with Got it!
  • After dismiss, an empty list shows the normal empty-state message instead
  • Dismissal is remembered; More → Tips & Assistance → Reset Tutorial restores it

Top Bar

The top bar contains:

  • Sort icon - Opens the set ordering screen so you can rearrange saved sets
  • Add icon - Creates a new saved set

Saved Set Card

Each set card may show:

  • Set name - The name you gave the set
  • Link icon - A small link beside the name when the set is included on Budget
  • Amount summary - A net total, or separate positive/negative badges when both income and expense are present
  • Transaction count - A small number showing how many matching transactions were found
  • Condition icons - Small icons summarizing what the set filters by
  • Period - The saved date range, such as Jan 1 - Now
  • More button - Opens actions for that set

Condition Icons

The icon row gives you a quick visual summary of the filters inside the set.

  • Section and category filters use the related section icons and colors
  • Account filters use the account group's icon
  • Contact filters use the contact type icon
  • Tag filters use a tag icon
  • Description filters use a note icon

Excluded conditions are shown with a red outline so you can tell them apart from included ones.

Opening a Saved Set

Tap a Set

Tapping a saved set opens a filtered transactions screen for the set's date range and conditions. Upcoming transactions can include recurring previews that match the same include/exclude conditions and amount limits. Previews are not saved transactions and do not enter the editor's matching counters or Mass Update. The Sets list's amount summaries use saved transactions; the transaction screen's Upcoming totals also include matching previews within its selected dates.

This is useful when you want to:

  • Review the matching transactions in detail
  • Edit individual transactions
  • Verify that the set is catching the right data

Analytics for a Set

Choose Analytics from the set’s menu to open its matching transactions for the set’s resolved period. Each drill-down keeps the set conditions: Vacation › Groceries › Store A shows only grocery transactions at Store A that belong to Vacation. Changing the analytics dates reloads that selection without changing the saved set itself.

Use the Transactions option inside analytics to inspect the matching purchases, or return through the compact breadcrumbs below the summary. See Analytics & Reports for breakdown availability, comparisons, and transaction grouping.

More Menu

Tap the three-dot button, or long-press the card, to open these actions:

  • Transactions - Opens the filtered transaction list
  • Analytics - Opens analytics for the matching transactions
  • Mass Update - Applies bulk changes to all matching transactions
  • Edit - Changes the set's name, period, or conditions
  • Add to Budget - Includes the set on Budget in every period, with no plan until you add one there. Shown when the set is not already on Budget. Requires Pro; otherwise the upgrade screen opens. If you upgrade and return, the set is included
  • Unlink from Budget - Replaces Add to Budget when the set is already on Budget. Removes it from Budget in every period without deleting the set or its saved plans. Available even without Pro
  • Delete - Removes the saved set after confirmation

Deleting a set does not delete the transactions inside it. It only removes the saved filter.

When an item used by a set is deleted

If you delete a tag, contact, category, section, or account that a set's conditions use, the set is updated automatically, without a separate warning. The deleted item is removed from those conditions. If it was the only item in a condition, that condition is removed. If the condition was the only one in its group, the group is removed too. The set then matches using its remaining conditions, so its transaction count and totals can change. For example, a set with only Tag: Trip matches all transactions (within its period and amount range) after the Trip tag is deleted. A set with has all of Trip, Hotel becomes has all of Hotel. Removing an item from an exclude condition does not change which transactions the set shows. Merging keeps sets pointing at the merged item instead.

Creating or Editing a Set

When you create or edit a set, the screen has Include and Exclude tabs in the top bar. The rest of the screen scrolls together: name, optional period, optional amount range, then the conditions for the selected tab.

The save button is the checkmark in the top bar. The ⋮ menu beside it opens Transactions, Analytics, and Mass Update for the name, period, amount, and conditions currently on the screen, including changes that are not saved. An empty name uses the create or edit title on those screens. If the end date is before the start date, the period error appears and the screen does not open. Leaving the editor without the checkmark still discards the set. Mass Update still changes the matching saved transactions. Recurring previews on Transactions → Upcoming still follow the last saved set; a set that has never been saved shows no previews.

Name

Every set needs a name. This is the title shown in the list.

Period

Period is optional. If no dates are set, the editor shows a compact Period chip under the name, on the same row as Amount when that filter is also unused. Tap Period to add:

  • Start date
  • End date

Each date field has an ×. If you clear a date and the other date is empty, the date fields hide and the Period chip returns. If you leave the end date empty, the set continues up to Now. If both dates are empty, the set can match transactions across all available time.

Amount range

Amount is also optional and applies to the whole set, not to a single group. If no amount range is set, the editor shows a compact Amount chip next to Period. Tap it to add Minimum amount and Maximum amount.

The collapsed amount line shows both limits with AND between them, such as >= 5 AND <= 6. Use × to remove the amount filter even if you have not entered values yet. The Amount chip then returns.

Include Tab

The Include tab defines what should match.

Conditions are grouped:

  • Conditions in the same group all have to match (AND)
  • Separate groups are alternatives (OR)

A new set starts with one group. Use Add condition inside a group to add another rule to that group. Use Add group to start an alternative combination. A grey OR divider appears between groups. Each group has an × on the Add condition row so you can remove it, including when there is only one group. Removing the last group leaves no include conditions, so the set can match any transaction in the period and amount range that is not excluded.

Dates and the amount range stay shared constraints above the groups. They apply to the whole set, not to a single group. They are not listed in Add condition.

Existing sets that used Any (OR) keep the same results: each of those conditions becomes its own group.

The Include tab also shows a running count of the final matching result: transactions that satisfy any include group, the shared dates and amount range, and are not removed by Exclude. Each condition tile shows its own count instead, so you can tell a single rule apart from that combined result. The Add condition row also shows how many transactions match that group alone.

Exclude Tab

The Exclude tab removes transactions from the result.

A transaction is removed if it matches any exclusion. Use this when you want a broad include rule but need to subtract certain categories, contacts, tags, accounts, or other values.

The Exclude tab count shows how many transactions match at least one exclusion in the chosen dates. Those transactions are the ones subtracted from the Include result.

Available Conditions

You can add conditions for:

  • Categories
  • Sections
  • Contacts
  • Tags
  • Accounts
  • Descriptions
  • Category types
  • Contact types

The amount range is added with the Amount chip, not from Add condition.

Already used fields stay available in Add condition. Each time you add the same field, it becomes a separate condition. For example, in the same group, one Tags condition can require any of #gift or #birthday, and another Tags condition can require a name that starts with alcohol/. Both must match. Put those conditions in different groups if either combination should be enough.

Each condition tile keeps the compact outlined field, floating label, icon, count, and × button. The floating label includes a short matching summary, such as Tags · All or Descriptions · Starts with. Long summaries are shortened so they still fit small screens.

Matching options are chosen inside the selector for that condition. Tap the condition tile to open it, then tap an outlined dropdown at the top to choose a matching option. Each dropdown shows only the current choice until opened. Tag dropdowns sit side by side when the translated labels and text size fit; they stack on narrower screens or with larger text. Other fields have one matching dropdown. The dropdowns, selected values, and text input share a compact form card with aligned edges. That card stays at the top of the screen, so the selected chips stay visible. Available values appear in a separate list below that scrolls on its own. The form stays put when the keyboard is open.

Changes apply to the condition as you select options or values. Use Back to return to the Set editor, then use its top-right checkmark to save the Set.

Tags

Tag conditions have two matching choices:

  • Combine values: Any, All, or None
  • Match names: Exactly, Starts with, Ends with, or Contains

Exactly uses the existing tag checklist. For a name pattern, choose Starts with, Ends with, or Contains, type in Tag name pattern, then tap the + button beside the input or submit from the keyboard to add it. Selected patterns appear above the input. Patterns also apply to tags you create later.

The list below the form previews current tag names. With an empty input it shows all names, regardless of selected patterns. As you type, it filters names using the chosen Starts with, Ends with, or Contains option, ignoring letter case. Changing that option updates the preview for the text still in the input. Tap a row to add its full tag name as a pattern using the current matching option. This clears the input and restores the full list. Tapping a name already selected does not add a duplicate or remove it; use its selected chip above to remove it.

A checkmark and teal highlighting identify names already selected or covered by any selected pattern. For example, selecting Starts with and adding alcohol/ checks both alcohol/beer and alcohol/wine. Checks use saved patterns, not text you have only typed into the input. They indicate coverage by a selected pattern, regardless of Any, All, or None; they do not indicate whether a transaction passes the complete Set. Tapping a covered row still adds its full name as a separate selected pattern. Remove patterns using the chips above.

Tap + or submit from the keyboard to add the typed text as a selected pattern. This clears the input and restores the full list. Selected patterns stay above the input and do not filter this preview. Clearing the input with its × button also restores the full list without changing your selections. A no-results message appears when no names match; you can still add the typed pattern.

Switching a tag-name pattern to Exactly selects the current tag names that match the previous Starts with, Ends with, or Contains option. The pattern becomes a fixed selection of those names, so newly created matching tags are no longer added automatically.

Any + Exactly is the default, so existing sets keep matching the same transactions.

You can also choose Is empty or Is not empty to find untagged transactions, or transactions that have at least one tag. These options hide the Combine values dropdown and value selection, since no selected tag or pattern is needed. The explanation distinguishes transactions with no tags from transactions with at least one tag.

Descriptions

Description conditions can use existing transaction descriptions or custom text values. Matching ignores letter case and spaces at the beginning or end of descriptions and selected text. A description containing only whitespace counts as empty. The original note text is preserved. Matching options are:

  • Contains (default, case-insensitive, same as before)
  • Does not contain
  • Starts with
  • Ends with
  • Equals
  • Does not equal
  • Is empty
  • Is not empty

The list below the input is a preview, showing up to 50 recent descriptions when the input is empty. Typing filters descriptions using the selected matching option, ignoring letter case; changing the option updates the preview. Tap a row to add its full description using the current matching option; this clears the input and restores recent descriptions. Tapping an already selected description keeps it selected without adding a duplicate. Tap + or submit from the keyboard to add your typed text to the selected values above. The input then clears and recent descriptions return. Selected values do not filter the preview. Clearing the input also restores recent descriptions without changing your selections.

Description rows also show a checkmark and teal highlighting when their full text is selected, or when a selected Contains, Starts with, or Ends with pattern covers them. Matching ignores letter case. For Equals, Does not equal, and Does not contain, checks identify explicitly selected text only. The checkmark shows selection coverage, not the final transaction results.

This is useful for catching merchants, notes, or keywords that are not covered by categories alone.

Other Fields

Categories, sections, accounts, category types, and contact types use:

  • Is any of (default)
  • Is none of

Contacts also include Is empty and Is not empty, so you can find transactions with no contact, or only transactions that have one.

Amount Range

The amount range filter lets you define:

  • Minimum amount
  • Maximum amount

Add it with the Amount chip. It applies to the whole set on both tabs. The preview uses AND between the minimum and maximum, and × removes the filter.

Live Counts

Each active condition shows a small counter for that condition alone, using the set’s dates. The Add condition row shows that group’s count. The Include tab count is the final matching result after all include groups, exclusions, dates, and the amount range. Transaction lists, analytics, and mass update use that same final matching result, including when you open them from the editor before saving.

Mass Update

Mass Update lets you change all transactions in a saved set together. Before applying changes, the screen shows how many transactions will be affected and warns that creating a backup is recommended.

Available bulk operations include:

  • Replacing the category
  • Replacing or clearing the contact
  • Adding, removing, replacing, or clearing all tags
  • Appending to, replacing, or clearing the description
  • Deleting all matching transactions

This is especially helpful for cleanup after imports, fixing repeated mistakes, or re-labeling a large group of transactions.

Note: Category replacement may be unavailable when the set contains a mix of income and expense transactions.

Reordering Sets

Tap the Sort button in the top bar to open the Set Order screen.

There you can:

  • Drag and drop sets into your preferred order
  • Control how sets appear on the main Saved Sets screen and the Budget Sets block
  • When opened through Budget’s Sets block, unwatched sets appear dimmed but can still be reordered; this does not add them to Budget

Empty State

If you have not created any sets yet, the screen shows a simple message indicating that no saved sets exist yet.

Watching sets on Budget

Pro users can enable Budget → Display Settings → Sets → Show Sets, then use Add Set in the block. On this screen, a link icon beside the name marks a set already included on Budget. Add to Budget or Unlink from Budget in the set menu changes that without opening the plan form. The watched list is global, follows this screen's set order, and uses the selected Budget dates instead of the saved set dates. Plan amounts are entered separately for each budget period, initially empty (no plan); entering 0 saves a real zero plan. The Expense/Income plan type is shared across periods for that set. Saved planned amounts, including 0, can be copied with Copy Plan into periods with no plan. The set-item display switches are independent of category settings; only actual amounts are shown by default. Plan type selection is always available, including for sets based on tags; new sets default to Expense. Use Unlink from Budget to stop watching a set without deleting it or its plans. See Sets on Budget for adding, removing, plan comparisons, display settings, and matching transactions.

Tips for Using Saved Sets

  1. Start broad, then exclude - It is often easier to include a large group first and then remove edge cases with the Exclude tab.
  2. Use clear names - Good names like "Groceries - Family - This Year" make sets easy to recognize later.
  3. Check transaction counts while building - The live counts help confirm that your conditions are matching what you expect.
  4. Use sets before mass edits - Open the transaction list first to verify the results before applying bulk updates.
  5. Use amount ranges for cleanup - Amount filters are helpful when you need to find repeated charges, salary payments, or suspicious duplicates.
